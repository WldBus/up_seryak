# Контракт API «Театральная касса»

Сделан по образцу учебного контракта `КОНТРАКТ-API.md` («Библиотека»): те же соглашения, оболочка списка, коды ошибок и требования к CORS. Отличаются только ресурсы — они под тему «Бронирование билетов в театр».

Сервер: `theatre-server.js`. Запуск:

```
node theatre-server.js --port 8080 --origin http://localhost:5555
```

Клиент — только с фиксированным портом: `flutter run -d chrome --web-port=5555`.

Базовый адрес по умолчанию: `http://localhost:8080/api`

Соответствие учебному API: книга → спектакль (`shows`), издательство → театр (`theatres`), автор → актёр (`actors`), жанр → жанр (`genres`), читатель → зритель (`spectators`), читательский билет → карта зрителя (`card`), выдача → бронирование (`bookings`), ISBN → код постановки.

---

## 1. Общие соглашения

- Формат обмена — JSON, кодировка UTF-8.
- Заголовок `Content-Type: application/json` обязателен для запросов с телом.
- Идентификаторы целочисленные, начинаются с 1.
- Служебные даты (`createdAt`, `deletedAt`) — ISO 8601 в UTC: `2026-10-22T08:55:32.587Z`.
- Дата спектакля (`date`) — местное время театра, без часового пояса: `2026-11-02T19:00:00`. Показ в 19:00 должен быть в 19:00 для любого зрителя.
- Все списки возвращают одинаковую оболочку с постраничной разбивкой.

### 1.1. Оболочка списка

```json
{ "items": [ /* объекты */ ], "page": 1, "size": 10, "total": 24, "totalPages": 3 }
```

### 1.2. Формат ошибки

| Код | Смысл | Тело |
|---|---|---|
| 400 | Некорректный JSON в теле | `{ "message": "..." }` |
| 401 | Не аутентифицирован (только с `--auth`) | `{ "message": "..." }` |
| 403 | Роль не позволяет (только с `--auth`) | `{ "message": "..." }` |
| 404 | Объект не найден | `{ "message": "..." }` |
| 405 | Операция недоступна для ресурса | `{ "message": "..." }` |
| 409 | Конфликт: на запись ссылаются или не хватает мест | `{ "message": "..." }` |
| 422 | Ошибка валидации полей | см. ниже |
| 500 | Внутренняя ошибка сервера | `{ "message": "..." }` |

```json
{
  "message": "Ошибка валидации",
  "errors": {
    "code": "Спектакль с кодом SP-1001 уже есть",
    "seatsAvailable": "Свободных мест не может быть больше, чем всего"
  }
}
```

Ключи `errors` совпадают с ключами полей формы клиента: `code`, `theatreId`, `actorIds`, а у карты зрителя — `card.number`, `card.issuedAt`, `card.discount`.

### 1.3. Учебные параметры

- `?__delay=1500` — задержка ответа в миллисекундах (до 10 000);
- `?__fail=500` — ответ с указанным кодом ошибки;
- `GET /api/__health` — проверка, что сервер запущен;
- `POST /api/__reset` — вернуть начальные данные.

## 2. Аутентификация и права

Без флага `--auth` сервер пускает всех (так было в ПР4). С ПР5 он запускается с `--auth`:

```
node theatre-server.js --port 8080 --origin http://localhost:5555 --auth
node theatre-server.js --port 8080 --origin http://localhost:5555 --auth --ttl 60
```

`--ttl` — срок жизни токена доступа в секундах (по умолчанию 900, то есть 15 минут). Токен обновления живёт 7 дней.

### 2.1. Учётные записи для проверки

| Логин | Пароль | Роль | Кто это |
|---|---|---|---|
| `admin` | `admin123` | `admin` | Администратор |
| `cashier` | `cashier123` | `cashier` | Кассир Петрова А. С. |
| `viewer` | `viewer123` | `viewer` | Зритель Иванов Сергей, привязан к зрителю 1 |

### 2.2. Адреса

- `POST /api/auth/register` — `{ "username", "password", "email", "fullName" }`. Ответ `201` — пользователь без пароля, роль всегда `viewer`. Проверки (`422`): логин от 3 символов, латиница, не занят; пароль от 8 символов, с цифрой и спецсимволом; формат почты; имя. Если в базе есть зритель с той же почтой, пользователь привязывается к нему (`spectatorId`) и видит его брони.
- `POST /api/auth/login` — `{ "username", "password" }`. Ответ `200`: `{ accessToken, refreshToken, expiresIn, user }`. Неверные данные — `401` «Неверный логин или пароль».
- `POST /api/auth/refresh` — `{ "refreshToken" }`. Ответ — новая пара токенов и свежий `user` (если администратор сменил роль, клиент узнает об этом здесь). Старый токен обновления сразу аннулируется; повторное использование — `401`.
- `GET /api/auth/me` — текущий пользователь по заголовку `Authorization: Bearer <accessToken>`.
- `POST /api/auth/logout` — `{ "refreshToken" }`, аннулирует токен обновления, ответ `204`.

Объект пользователя: `{ id, username, fullName, email, role, spectatorId, createdAt }`.

Роль сервер берёт из своей базы по подписанному токену, а не из того, что прислал клиент. Без токена или с истёкшим токеном — `401`, при нехватке прав — `403` с текстом вида «Недостаточно прав: операция доступна роли «Кассир», «Администратор»».

### 2.3. Права ролей

Роли не вложены друг в друга: у каждой свой набор действий.

| Операция | viewer | cashier | admin |
|---|---|---|---|
| Просмотр спектаклей, театров, актёров, жанров | да | да | да |
| Свои бронирования (`GET /api/bookings` — только свои), продление своей брони | да | нет | нет |
| Создание, изменение, логическое удаление спектаклей и справочников | нет | да | да |
| Просмотр и изменение зрителей | нет | да | да |
| Все бронирования, оформление и закрытие броней («Касса») | нет | да | нет |
| Физическое удаление, восстановление | нет | нет | да |
| Пользователи и роли, статистика | нет | нет | да |

### 2.4. Пользователи и статистика (только `admin`)

- `GET /api/users` — список (`search`, `role`, `sort`, `page`, `size`).
- `PATCH /api/users/{id}` — `{ "role": "viewer" | "cashier" | "admin" }`. Свою роль изменить нельзя — `409`.
- `GET /api/stats` — `{ shows, theatres, actors, spectators, users: {viewer, cashier, admin}, bookings: {active, paid, cancelled, expired}, seatsSold, revenue, topShows: [{id, title, sold, seatsTotal}] }`.

## 3. Ресурсы

Для `shows`, `theatres`, `actors`, `genres`, `spectators` действует один и тот же набор операций. Ниже он показан на примере спектаклей.

| Метод и адрес | Что делает | Ответ |
|---|---|---|
| `GET /api/shows` | страница списка | `200` оболочка |
| `GET /api/shows/{id}` | одна запись, `?includeDeleted=true` — и удалённая | `200` / `404` |
| `POST /api/shows` | создание | `201` / `422` |
| `PUT /api/shows/{id}` | изменение, тело как у POST | `200` / `404` / `422` |
| `DELETE /api/shows/{id}` | логическое удаление | `204` / `409` |
| `DELETE /api/shows/{id}?hard=true` | физическое удаление | `204` / `409` |
| `POST /api/shows/bulk-delete` | логическое удаление нескольких, тело `{ "ids": [1, 2] }` | `200 { "deleted": 2 }` / `409` |
| `POST /api/shows/{id}/restore` | восстановление | `200` |

Общие параметры списка: `search`, `sort` (`поле,asc` или `поле,desc`), `page` (с 1), `size` (по умолчанию 10, максимум 100), `includeDeleted` (`true`/`false`).

| Ресурс | `search` ищет по | Фильтры | Поля `sort` |
|---|---|---|---|
| `shows` | названию и коду | `genreId`, `theatreId`, `actorId`, `priceFrom`, `priceTo` | `title`, `date`, `price`, `duration` |
| `theatres` | названию и городу | — | `name`, `city`, `hallSeats`, `founded` |
| `actors` | фамилии, имени, стране | `theatreId` | `lastName`, `country`, `birthYear` |
| `genres` | названию и описанию | — | `name`, `id` |
| `spectators` | фамилии, имени, почте, номеру карты | — | `lastName`, `email`, `discount` |

Пример: `GET /api/shows?search=озеро&genreId=4&sort=price,desc&page=1&size=10`

### 3.1. Когда удалить нельзя (409)

- театр — если на него ссылаются спектакли или актёры;
- жанр — если он указан у спектаклей;
- актёр — если он занят в спектаклях;
- спектакль и зритель — физически, если на них есть бронирования.

Логически удалённые спектакли тоже считаются ссылками: их можно восстановить. `bulk-delete` не удаляет ничего, если хотя бы одну из записей удалить нельзя. Текст ответа содержит число связанных записей.

### 3.2. Бронирование

Бронь держится 3 дня (`expiresAt`), потом сгорает (`expired`), и места возвращаются в продажу. Статусы: `active` — действует, `paid` — выкуплена, `cancelled` — отменена, `expired` — сгорела.

- `POST /api/bookings` (кассир) — тело `{ "spectatorId": 1, "showId": 2, "seats": 2 }`, от 1 до 10 билетов. Ответ `201`, у спектакля уменьшается `seatsAvailable`. Если свободных мест меньше, чем запрошено, — `409` с текстом вида «На спектакль «Щелкунчик» свободных мест нет».
- `POST /api/bookings/{id}/extend` (зритель, только своя бронь) — продлить ещё на 3 дня, один раз. Повторно или для закрытой брони — `409`.
- `POST /api/bookings/{id}/close` (кассир) — `{ "result": "paid" | "cancelled" }`: выкуп или отмена. При отмене места возвращаются. Уже закрытая бронь — `409`.
- `GET /api/bookings` (фильтры `status`, `showId`, `spectatorId`, `search`) и `GET /api/bookings/{id}` — просмотр: кассир и администратор видят все, зритель — только свои.
- Изменять и удалять бронирования напрямую нельзя — `405`.

## 4. Модели

### `Show` — чтение

```json
{
  "id": 1,
  "title": "Лебединое озеро",
  "code": "SP-1001",
  "date": "2026-11-02T19:00:00",
  "duration": 165,
  "price": 6500,
  "theatre": { "id": 1, "name": "Большой театр" },
  "genres": [ { "id": 4, "name": "Балет" } ],
  "actors": [ { "id": 1, "fullName": "Орлова Анна" } ],
  "seatsTotal": 400,
  "seatsAvailable": 12,
  "createdAt": "2026-10-22T08:55:32.587Z",
  "deletedAt": null
}
```

### `Show` — запись (POST, PUT)

```json
{
  "title": "Лебединое озеро",
  "code": "SP-1001",
  "date": "2026-11-02T19:00:00",
  "duration": 165,
  "price": 6500,
  "theatreId": 1,
  "genreIds": [4],
  "actorIds": [1],
  "seatsTotal": 400,
  "seatsAvailable": 12
}
```

На запись уходят `theatreId`, `genreIds`, `actorIds`, а приходят развёрнутые `theatre`, `genres`, `actors` — как у книги в учебном API. Клиентская модель `Show.fromJson` понимает обе формы.

### `Theatre`

```json
{ "id": 1, "name": "Большой театр", "city": "Москва", "address": "Театральная пл., 1", "hallSeats": 1740, "founded": 1776, "deletedAt": null }
```

### `Genre`

```json
{ "id": 4, "name": "Балет", "description": "Сюжет передаётся танцем и музыкой", "deletedAt": null }
```

### `Actor`

```json
{ "id": 1, "lastName": "Орлова", "firstName": "Анна", "country": "Россия", "birthYear": 1990, "theatreId": 1, "deletedAt": null }
```

### `Spectator`

```json
{
  "id": 1,
  "lastName": "Иванов",
  "firstName": "Сергей",
  "email": "ivanov@mail.ru",
  "phone": "+79161234567",
  "card": { "id": 1, "number": "100001", "issuedAt": "2024-03-12T00:00:00", "discount": 5 },
  "deletedAt": null
}
```

Карта зрителя — один к одному. На запись она передаётся вложенным объектом `card` без `id`, сервер хранит её отдельно и пишет вместе со зрителем.

### `Booking`

```json
{
  "id": 3,
  "spectator": { "id": 1, "fullName": "Иванов Сергей" },
  "show": { "id": 1, "title": "Лебединое озеро", "date": "2026-11-02T19:00:00", "price": 6500 },
  "seats": 2,
  "status": "active",
  "expiresAt": "2026-10-30T09:00:00.000Z",
  "extended": false,
  "closedAt": null,
  "createdAt": "2026-10-27T09:00:00.000Z",
  "deletedAt": null
}
```

## 5. Проверки сервера (422)

Те же, что в формах клиента. Сервер проверяет их ещё раз, потому что клиента можно обойти.

| Ресурс | Поле | Правило |
|---|---|---|
| `shows` | `title` | 2–100 символов |
| | `code` | формат `SP-0000`, уникален без учёта регистра |
| | `theatreId` | театр существует и не удалён |
| | `actorIds` | хотя бы один, все из труппы выбранного театра |
| | `genreIds` | хотя бы один, жанры существуют |
| | `date` | корректная дата |
| | `duration` | 30–300 |
| | `price` | 1–50 000 |
| | `seatsTotal` | 1–5000 |
| | `seatsAvailable` | от 0 и не больше `seatsTotal` |
| `theatres` | `name` | 2–80, уникально в пределах города |
| | `city` | 2–50, только буквы |
| | `address` | 5–120 |
| | `hallSeats` | 1–10 000 |
| | `founded` | 1500..текущий год |
| `genres` | `name` | 2–40, только буквы, уникально |
| | `description` | до 300 |
| `actors` | `lastName`, `firstName`, `country` | 2–50, только буквы |
| | `birthYear` | 1900..(текущий − 10) |
| | `theatreId` | театр существует и не удалён |
| `spectators` | `lastName`, `firstName` | 2–50, только буквы |
| | `email` | до 100, формат почты, уникальна |
| | `phone` | `+7` и 10 цифр |
| | `card.number` | ровно 6 цифр, уникален |
| | `card.issuedAt` | корректная дата |
| | `card.discount` | 0–50 |

## 6. CORS

Как в учебном контракте: на каждый ответ — `Access-Control-Allow-Origin: <адрес клиента>`, `Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS`, `Access-Control-Allow-Headers: Content-Type, Authorization`, `Access-Control-Max-Age: 86400`. На `OPTIONS` по любому адресу — `204` с теми же заголовками. Разрешённый адрес задаётся флагом `--origin`.
